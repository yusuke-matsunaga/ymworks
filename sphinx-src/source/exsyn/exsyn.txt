	Exact Synthesis 覚え書き

1. Exact Synthesis とは
n入力演算子をk個組み合わせて与えられた論理関数を実現する論理回路を合
成する問題．
ファクタードフォームとは異なり一つの演算子を複数用いることができるので
結果はDAGとなる．
用いることの演算子に特に制約はなく，n入力関数(2^n個の真理値表)であれば
なんでもOK．

2. Exact Synthesis の戦略
元の論文では最初にすべて論理変数にエンコーディングしてSATソルバで解く
方法が書かれているが，もともとが述語論理の問題を命題論理に変換すること
は特に効率的とは思えないので，トポロジーの探索と演算子タイプの探索を
切り離して後半をSATソルバで解く方が個々の問題がシンプルになってわかり
やすい．元の論文でも後半は同様のアプローチを用いている．

3. トポロジの探索

3.1. Boolean chain
DAGはその性質上トポロジカルソートすることができるので，
k個の演算(ノード)からなるDAGのトポロジ情報とは
k個のノードのファンインの情報をトポロジカル順に
並べたもので表される．
これに加えて各演算のタイプ(真理値表など)の情報を加えたものを
Boolean chain と呼ぶ．
Exact Synthesis とは与えられた論理関数を実現する Boolean chain
を求める問題とみなすことができる．

3.2. トポロジに関する基本的な制約
論理演算は交換則，結合則が成り立つので異なる構造で同一の論理関数を表す
ことができる．また，同一のDAGに対しても複数のトポロジカル順が考えるこ
とができる．
このこと自体は正しい答を求める時の問題とはならないが，
このことを無視すると無駄な探索を行うことになり効率が悪い．
そこで，以下の制約を設ける．

- 同一のノードのファンインはノード番号の昇順に並べる．
  ただし，この制約を課すためには論理演算のタイプで入力順の入れ替えに対
  する同値類(P同値類)をすべて含んでいる必要がある．
- 前後するノードxとノードyのファンインに関して辞書式順序で
  ノードxのファンイン <= ノードyのファンイン
  の関係が成り立つ．
  ここで等号を含めているのは同一のファンインで異なる論理演算
  のノードが存在するため．


3.1. fence
DAGは入力からレベルを定めることができる．
具体的には入力をレベルをすべて0とする．
ノードyのファンインを x1, x2, ..., xn とすると
ノードyのレベルy_levelは次式で表される．

y_level = max(xi_level) + 1

fence とは個々のレベルごとのノード数のリストである．
例えば3つの演算子で最大レベルが3のDAGはすべての
演算子が直列につながった構造をしているので
(1, 1, 1)と表される．
またレベル1に2つの演算子がありレベル2に1つの演算子がある
DAGのfenceは(2, 1)と表される．
同じ演算子数k，同じ最大レベルlを持つ fence の集合を
fence family と呼び．F(k, l)で表される．
fence に関する制約は以下の通り．

- すべての要素の和が k と等しくなる．
- すべての要素の値は 1 以上となる．0はありえない．
- 最後のレベルの要素数は出力数以下
- 最後から一つ前のレベルの要素数は出力数*演算子の入力数以下
  具体的には二項演算で1出力関数を合成する問題の場合，
  最後のレベルの要素数は1，その一つ前のレベルの要素数は
  2以下でなければならない．

fence が決まってもDAGの構造には多くの自由度が残っているが，
各演算のファンインに関しては以下の制約が課される．
- 最低一つのファンインは直前のレベルのノードでなければならない．


3.2. Partial DAG
Partial DAGとはBoolean chainのトポロジ情報から入力に関する情報を
取り除いたものである．つまり，演算ノード間の接続情報のみを持つことにな
る．
Partial DAG は k個のファンイン情報の順列となる．
一つの fence から複数の Partial DAG を生成されることになる．
その際，トポロジに関する基本的な制約と元となる fence の制約をすべて満
たすものだけが選ばれる．

3.3. Partial DAGの列挙

# 全体のアルゴリズム
for k in range(k_max):
  for l in range(1, k + 1):
    fence_list = generate_fence(k, l)
    for fence in fence_list:
      pd_list = generate_pd(fence)

generate_fence() と generate_pd() の実装に関しては
c++-srcs/exsyn/utils/pdgen.py を参照のこと．


4. 論理演算タイプの探索
Partial DAG が与えられたら残るは外部入力の割り当てと論理演算タイプの割
り当てはSATソルバを用いて解く．
論理演算タイプに関しては真理値表の出力のビットを命題変数にして結果の論
理関数が等しくなるような制約を加えれば良い．
問題は外部入力の割り当てである．
元の論文ではこれに関していくつかの符号化を紹介している．

4.1. SSV
Single Selecter Variable の略で一つの変数ですべてのファンインの割り当
てを表すものである．
S_ijk = 1 の時，ノードiの2つのファンインが j と k であることを表す．
もちろん，S_ijk = S_ij'k' = 1 となってはいけないので(i != i', j != j')，
すべての S_ijk に対して one-hot 制約を設ける必要がある．
jkの組み合わせは n^2 のオーダーとなる．ここで n は入力数である．
ファンイン間の順序制約を設けても大まかに半分になるだけでオーダーは変わらない．
さらに3項演算なら3乗，4項演算なら4乗となる．

4.2. MSV
Multi Selecter Variable の略で少し特殊な符号化を行う．
具体的には S_ij = 1 の時，ノードiのファンインにjが含まれていることを表
す．
2項演算の場合は同じiに対して S_ij = 1 となるjが2つ存在するので
すべての S_ij に対して 2-hot 制約を設ける必要がある．
3項，4項でも同様．
この符号化ではノードiの最初のファンインがなんであるかが即座にはわから
ない．
具体的には AND(S_ik = 0 (k < j)) and S_ij = 1 という条件が必要となる．
3項，4項となるとさらに複雑な式となる．

4.3. OSV
Ordered Selecter Variable の略でファンインごとに順序制約を設ける．
順序制約とは n 個の変数を用いて 0 〜 n の値を表す符号化方式である．
k 番目の値を表すのにk番目の変数だけではなく，
最初からk番目の変数までのすべてを1にする．
つまり，常に1のビットが左半分，0のビットが右半分になるように制約が設け
られている．
このためk番目の値が選ばれているかのチェックに x_k = 1 and x_(k+1) = 0
が必要となるが，one-hot 制約と異なり常に O(n) の節しか必要としない．
また，2つの割り当ての間の順序制約も O(n) で表される．
one-hot 制約の場合は個々の要素間になんの関係もないので順序関係を表すた
めには順序関係の成り立つ要素数であるO(n^2)の制約節を必要とする．


5. 実装の詳細

5.1. 前処理
まず与えられた論理関数に対して前処理を施す．内容は以下の通り．

- 定数関数の除外
  0 または 1 に縮退している関数は自明なので除外する．
  定数関数を除外することにより Boolean chain に定数入力は不要となる．

- 同値関数の除外
  同値(等価)な出力がある場合は1ににまとめる．

- 正規化
  (0, 0, ..., 0) に対する出力が 0 になるように出力の極性を正規化する．
  反転した出力に対しては結果の出力を反転させる．
  元となる関数を正規化することにより各演算も正規化したものだけを考えれ
  ばよいことになる．
